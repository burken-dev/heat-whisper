# ESP32-S3 RS485 board support (design)

Date: 2026-09-20. Status: approved (approach A + all sections confirmed by user).

## Problem

Only ESP32 classic (`esp32dev` TX17/RX16) and Pico W are supported. Waveshare
ESP32-S3-RS485-CAN has onboard isolated RS485 (no external transceiver) but
different SoC, pins, and manual DE control — no YAML target exists.

## Decisions (from brainstorming Q&A)

- Board: Waveshare ESP32-S3-RS485-CAN (S3R8, 16M flash / 8M PSRAM).
- Wiring: pump A/B straight to onboard isolated screw terminals; 7–36V DIN
  power; 120R jumper ON when single end-device bus.
- RS485 pins: TX=GPIO17, RX=GPIO18, EN=GPIO21 — manual direction via
  `flow_control_pin: GPIO21` (not auto-direction; confirmed by YamBMS/Tesla users).
- Framework: Arduino, `logger: baud_rate: 0` silent — same as classic (minimal diff).

## Rejected alternatives

- **B — Unified substitutions** (one `esp32_base` with pin/board defaults):
  less duplication but touches working classic config. Rejected (regression risk).
- **C — S3-native IDF + octal PSRAM + USB-CDC logs**: best long-term but
  bigger diff, needs testing. Rejected per user pick; revisit if Arduino/PSRAM
  limits hit.

## Architecture (chosen, Approach A)

Two new thin wrappers, zero C++ change (`tx_()` already toggles `flow_pin_`
in `heatwhisper.cpp:155-159`):

1. `packages/esp32_s3_rs485.yaml`: `esp32: board esp32-s3-devkitc-1,
   framework arduino` + `uart: id heatwhisper_uart TX17/RX18 9600 8N1` +
   `heatwhisper.flow_control_pin: GPIO21`. Reuses `packages/base.yaml` as-is.
2. `heatwhisper_esp32_s3_rs485.yaml`: top-level (`base` + `esp32_s3_rs485` +
   local components), mirroring `heatwhisper_esp32.yaml`.

## Data flow

Unchanged protocol: pump A/B → onboard transceiver → UART1 → existing
`loop()` decode/ACK/slot-TX. `flow_pin` HIGH during `tx_()`, LOW after.
Bring-up unchanged: `passive: true` decode-only, then TX on.

## Error handling

- Wrong DE wiring (EN floating) = silent TX fail; fixed by GPIO21 default in package.
- A/B swap = no decode in passive mode; swap and re-check logs.
- 120R mismatch = reflections on long runs; jumper ON for single-drop bus.

## Build / release

- CI (`.github/workflows/build.yml`): add `esphome config + compile
  heatwhisper_esp32_s3_rs485.yaml`; copy `firmware.factory/ota.bin` to
  `fw/` + release aliases `heatwhisper_esp32_s3_rs485.factory/ota.bin`.
- `manifest.json`: add `{chipFamily: ESP32-S3}` build entry (web flasher
  supports S3). `index.html`: S3 section.
- README hardware table: S3 row (TX17/RX18/EN21, 7–36V, jumper note).

## Testing

- `esphome config` + `compile` new YAML, `pytest` unchanged (no logic change).
- Manual: passive decode → active ACK on pump. No new C++ tests.

## Non-goals

ESP-IDF, PSRAM tuning, USB-CDC logs, CAN bus, relay variants, per-model YAML.
