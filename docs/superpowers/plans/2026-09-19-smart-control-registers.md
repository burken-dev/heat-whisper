# Smart-Control Registers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose 9 additional registers (3 sensors + 6 numbers) so Home Assistant can do solar/price/weather optimization via heat offset/curve and hot-water mode.

**Architecture:** No new C++ platforms (ponytail: reuse existing `sensor`/`number` + `set_register_enabled` switches). Extend `DEFAULT_ALLOWLIST` so firmware decodes new addrs; add YAML entities in `packages/base.yaml` (entity + enable-switch + `on_boot` line each); regenerate `registers.h`; update tests + README.

**Tech Stack:** ESPHome YAML, Python codegen (`components/nibe/registers.py`), C++ (`nibe.cpp` linear `NIBE_COMMON` scan), pytest host tests.

## Global Constraints

- No control logic on-device — telemetry + write-passthrough only (README non-goals).
- Writes to addr < 20000 are dropped, never sent in `0x6B` slot (`nibe.h:48`).
- Every `sensor:` carries `delta: 0.1 / throttle: 60s / heartbeat: 5min` anti-spam block.
- Every entity gets `Enable …` template switch (`optimistic: true`, `RESTORE_DEFAULT_ON`) + one `on_boot` lambda re-assert.
- `registers.h` is build-generated by `__init__.py:to_code` via `generate_header()` — checked-in copy must match.
- Stdlib only in scripts/tests; no new dependencies.
