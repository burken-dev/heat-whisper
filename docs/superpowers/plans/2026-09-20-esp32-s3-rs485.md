# ESP32-S3 RS485 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Waveshare ESP32-S3-RS485-CAN as a third build target with zero C++ changes.

**Architecture:** Two thin YAML wrappers (`packages/esp32_s3_rs485.yaml` + `heatwhisper_esp32_s3_rs485.yaml`) mirroring the existing esp32/pico pattern; `flow_control_pin: GPIO21` drives the existing `tx_()` DE toggle. CI/manifest/flasher/docs extended per board.

**Tech Stack:** ESPHome (Arduino framework), YAML, GitHub Actions, ESP Web Tools manifest.

## Global Constraints

- Zero C++ changes (`components/heatwhisper/*` untouched — `flow_pin_` toggle already exists).
- `logger: baud_rate: 0` stays (silent, from `packages/base.yaml`).
- Arduino framework (not ESP-IDF), no `psram:` line, no USB-CDC logs.
- UART 9600 8N1; TX GPIO17, RX GPIO18, EN GPIO21.
- Node name `heat-whisper-s3` (must differ from `heat-whisper` / `heat-whisper-pico`).
