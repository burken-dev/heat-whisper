# MODBUS40-only (drop RMU) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** NIBE-bus mode emulates only MODBUS40 (`0x20`); RMU slot concept deleted; standard Modbus-RTU path unchanged.

**Architecture:** Hard-code `kModbus40Addr = 0x20` in the NIBE slave path and rename the overloaded `peer_` to `modbus_addr_` (RTU slave address only). Delete peer NVS, RMU branches, selector UI, `RMU40_S*.json`. Keep `0xEE→0x20` version bytes and the `<20000` write guard.

**Tech Stack:** C++ (ESPHome component), Python (codegen `__init__.py`), pytest source-contract tests, host `g++` harness for `nibe.h`.

## Global Constraints

- NIBE-bus slave address is always `0x20`; no UI/YAML knob for it.
- Delete `RMU40_S1–S4.json` maps; keep `is_writable` guard.
- `0xEE→0x20` version reply stays byte-identical (`C0 EE 03 EE 03 01 C1`).
- Single user: orphan stale `HW_PEER_TYPE` NVS, no migration.
- Every task ends green (`pytest tests/ -v`) before commit.
