# Runtime Log Level via ESPHome select.logger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Configure ESPHome native `select.logger` with `initial_level: INFO` in `packages/base.yaml` so the Web UI log console is clean by default while allowing on-the-fly toggling to `DEBUG` for troubleshooting.

**Architecture:** Update `packages/base.yaml` to set `level: DEBUG` and `initial_level: INFO` under `logger:`, and add a top-level `select:` block with `platform: logger`. Validate with unit tests in `tests/test_config.py` and ESPHome config schema validation across all 3 hardware targets.

**Tech Stack:** ESPHome YAML, Python (pytest).

## Global Constraints

- Native ESPHome components only (zero custom C++ or NVS boilerplate).
- Base compiled logger level must be `DEBUG` so debug messages remain compiled in the binary.
- Initial runtime level must be `INFO` to suppress continuous `[D][sensor:...] Sending state...` spam.
- Entity category must be `config`.

logger:

  baud_rate: 115200
  level: DEBUG
  initial_level: INFO

select:
  - platform: logger
    name: "Log Level"
    entity_category: config
